# Grasp Tested-By Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every function card says which tests reach it — a `n tests` badge and a Tests section in its callers menu — and a review against a base ref says which changed functions no test reaches and which changed tests go with which changed code; the agent asks the same questions over MCP.

**Architecture:** One pure function on the index, `Grasp.Index.tests_for/3`, walks backwards from a function over the callers map the index already builds at load (Task 1). The viewer asks it for the functions on screen and for the changed functions, when the index or the set of functions shown changes rather than on every render (Tasks 2–3). Two MCP tools wrap it (Task 4). Docs close it (Task 5).

**Tech Stack:** Elixir, Phoenix LiveView, the MCP server (`anubis_mcp`), CSS, Markdown.

**Spec:** `docs/specs/2026-09-28-grasp-tests-design.md` §Tested by (milestone 10.2) — the authority for every rule below; §Test records for what a test record is.

## Global Constraints

- Public repo: never name any other project or a local filesystem path anywhere in the repo or commit messages; fixture names stay within `SampleApp`/`acme`. Every public Elixir function has `@doc` and `@spec`; every module a `@moduledoc`; HEEx components use `attr`, never `@spec`. Comments and docs state durable facts, never history ("was", "now", "previously", "no longer", "per review", "new" as in "the new badge", "today", "changed", "used to" are forbidden).
- Gates from `grasp/`: `mix format --check-formatted`, `mix compile --warnings-as-errors`, `mix test`; tasks touching `grasp/assets/**` run `mix assets.build` (no warnings) and commit `grasp/priv/static/assets/grasp.js`/`grasp.css`. Read exit codes directly (`; echo $?`, never through a pipe); never commit on a failed gate. Known flake: `Grasp.ReindexerTest` debounce — re-run once and report both runs. Never `git add -A`; add by path; never stage `grasp/priv/static/assets/app.js`/`app.css`. Commit trailer exactly `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`.
- The fixture index `grasp/test/fixtures/index.json` is regenerated only by the recipe at the top of `grasp/test/fixtures/regenerate.exs`; frozen fixture files are never edited (`greeter.ex`, `formatter.ex`, `hello_live.ex`, `greeting_component.ex`, `greet_html.ex`, `show.html.heex`, `router.ex`, lines 1–15 of `greet_controller.ex`); never run `mix format` inside the fixture app. Existing viewer tests keep passing unmodified; a test that needs a fixture shape the index lacks builds its own index document in the test rather than editing the shared fixture, unless the fixture change is regenerated by the recipe from a fixture-app change.
- Never run the real `gh`, `claude` or the network in tests.
- Performance: nothing computes reach on every render, and nothing walks forward from every test. A walk is bounded by `max_hops` and visits each record at most once.

### Task 1: `Grasp.Index.tests_for/3`

**Files:** modify `grasp/lib/grasp/index.ex`; tests in `grasp/test/grasp/index_test.exs`.

**Rules (the spec, §Tested by, Reach):**
1. `tests_for(index, id, max_hops \\ 4)` resolves `id` through the index's aliases as `callers/2` does, then walks backwards breadth-first over `index.callers`, one hop per caller step, for at most `max_hops` hops, visiting each record once. Every record met whose `kind` is `"test"` is collected at the hop it was first met. Every record met whose `kind` is `"setup"` contributes every test record of its `module` at the setup's hop, unless that test was already met nearer. The walk continues through test, setup and helper records as through any other (a helper calling the function is how most tests reach it).
2. The answer is `[%{test: test_id, hops: n}]` sorted by `hops`, then `test_id`. A function no test reaches answers `[]`, and so does an unknown id. A test or setup record is walked from like any record, so a test answers the tests that call it, which is usually none.
3. `hops` counts edges: a test calling the function directly is `hops: 1`.
4. `Index` holds what the walk needs without scanning every record per call: tests grouped by module (for setups) are built once at load, beside the existing `tests` field.

- [ ] **Step 1: Tests** with hand-built index documents (`Index.from_document/1`): a direct test (1 hop); a test through a helper (2); through a route call (a test with a `route` call to a controller action which calls the function — 2); a setup calling the function giving every test of its module; the nearest distance kept when two paths exist; `max_hops` cutting a 5-hop path at 4 and honouring an explicit `2`; a cycle (a → b → a) terminating; alias resolution (a default-argument arity); sort order. Plus one test against the shared fixture index for a function the fixture's tests call. Run; expect failure.
- [ ] **Step 2: Implement.** Run the file, then the suite.
- [ ] **Step 3: Gates and commit.** Message: `The index says which tests reach a function` plus trailer.

### Task 2: The tests badge and the callers menu's Tests section

**Files:** modify `grasp/lib/grasp_web/live/review_live.ex`, `grasp/lib/grasp_web/components/card_components.ex`, `grasp/assets/css/app.css`; rebuild bundles; tests in a view test file (`grasp/test/grasp_web/live/tests_live_test.exs` or a sibling).

**Rules (the spec, §Tested by, Card):**
1. The LiveView keeps an assign mapping each function id on the canvas to its `tests_for` answer, recomputed only when the index changes or the set of function ids on the canvas changes — never on a move, a focus, a comment or a render that changes neither. A test or setup card gets no entry.
2. A function card whose answer is non-empty wears a `n tests` badge in its header (`1 test`, `n tests`), in the header's badge idiom. A card whose answer is empty wears nothing.
3. The callers menu gains a **Tests** section after the callers, listing the tests nearest first, each row the test's title as a test card titles itself (`describe › name` or the name) and its hop count (`direct` for 1, `n hops` otherwise). Clicking a row opens that test's card as a caller opens (same event and placement the callers rows use). The badge opens the callers menu.
4. The menu's existing behaviour — one menu open at a time, server state `callers_open`, closing a rename — is unchanged.

- [ ] **Step 1: Tests** against the fixture index: a function the fixture's tests reach shows the badge with the right count; a function none reaches shows none; the Tests section lists the tests with hop labels; clicking one opens the test card as a caller; the assign is not recomputed on `move_cards` (assert via a counter or by the answer's identity — choose a test seam that does not reach into private state, e.g. a telemetry event or a message the LiveView sends itself; explain the seam in the report). Run; expect failure.
- [ ] **Step 2: Implement**, CSS for the badge, `mix assets.build`.
- [ ] **Step 3: Gates and commit** (bundles). Message: `A card says how many tests reach it, and its callers menu lists them` plus trailer.

### Task 3: Untested changes and paired changes in PR mode

**Files:** modify `grasp/lib/grasp_web/components/sidebar.ex`, `grasp/lib/grasp_web/live/review_live.ex` (only what the groups need), `grasp/lib/grasp/index.ex` if a reader is needed, `grasp/assets/css/app.css`; rebuild bundles; view tests.

**Rules (the spec, §Tested by, PR mode):**
1. The Changes group marks every changed application function (a changed record that is not a test, setup or test-module helper, and not removed) that `tests_for` answers `[]` for with an `untested` mark on its row.
2. An **Untested changes** group, directly after Changes, lists those functions by module like Changes does, when there is at least one; its rows open cards as Changes rows do; its open/closed state follows the sidebar's other groups (it opens on arrival when it has rows, as Changes does).
3. Under each changed application function in the Changes group, the changed tests (`change` other than `unchanged`, kind `test`) that reach it are listed as indented rows titled as test cards title themselves, each opening its test card as a new root.
4. The answers are computed once per index load (the changed functions are known at load), not per render.

- [ ] **Step 1: Tests.** The shared fixture's changes may not include a changed test; build an index document in the test (or regenerate the fixture through the recipe after a fixture-app change) holding a changed function reached by a changed test, a changed function reached by an unchanged test, and a changed function no test reaches. Assert the `untested` mark, the Untested changes group and its rows, the paired test row under the first function and none under the second. Run; expect failure.
- [ ] **Step 2: Implement**, CSS, `mix assets.build`.
- [ ] **Step 3: Gates and commit** (bundles). Message: `A review names the changes no test reaches and pairs the rest with their changed tests` plus trailer.

### Task 4: MCP `tests_for` and `untested_changes`

**Files:** create `grasp/lib/grasp/mcp/tools/tests_for.ex` and `grasp/lib/grasp/mcp/tools/untested_changes.ex`; register them where the other tools are registered (grep `GetCallers` in `grasp/lib/grasp/mcp/`); tests beside the other MCP tool tests (grep `get_callers` in `grasp/test`).

**Rules (the spec, §Tested by, MCP):**
1. `tests_for(function_id, max_hops?)` — `max_hops` an integer 1–8, default 4 — answers `{"id", "tests": [{"id", "name", "describe", "file", "hops"}]}` from `Index.tests_for/3`; an unknown id is the tools' usual not-found error.
2. `untested_changes()` answers `{"functions": [{"id", "file", "change"}]}` — the changed application functions no test reaches, sorted by id — and `{"functions": []}` with no base ref.
3. Descriptions state what each answers and that a test's id quotes its name, in the wording the other tools use.
